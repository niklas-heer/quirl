  Install the supported release with Homebrew or download a SHA-256-pinned
  native archive from the immutable
  [v0.1.0 GitHub Release](https://github.com/niklas-heer/quirl/releases/tag/v0.1.0).
</Callout>

## Homebrew

```sh
brew install niklas-heer/tap/quirl
```

The formula selects a SHA-256-pinned native binary for macOS or Linux on ARM64
or x86_64. It installs `quirl` plus its redistribution license files; its
bounded offline test does not download the completion database or command
model.

## Direct release archive

Download the package for your operating system and architecture from the
[v0.1.0 GitHub Release](https://github.com/niklas-heer/quirl/releases/tag/v0.1.0),
verify it against `SHA256SUMS`, and compare the entry in
`release-manifest-v1.json` before putting `quirl` on `PATH`. Never use an asset
from a mutable branch URL as a release binary.

## Binary requirements

The native package needs only a supported Linux or macOS host. It does not
require Git, Rust, Python, or a system Lua installation.

## Source-build requirements

- Linux or macOS for the supported interactive experience.
- Git.
- Rustup. The repository pins Rust 1.97.1 with `clippy` and `rustfmt`.
- Python 3 only for the Unix PTY quality gate.

You do not need a system Lua installation. The current source tree embeds
vendored Lua 5.5.1; the supported `v0.1.0` artifacts retain Lua 5.4.

## Build and run

```sh
git clone https://github.com/niklas-heer/quirl.git
cd quirl
cargo run -p quirl-cli
```

For a guided, text-only tour of the major surfaces, first install the official
release with Homebrew. The tour deliberately uses that release rather than a
binary compiled from the checkout:

```sh
brew install niklas-heer/tap/quirl
cargo xtask demo
```

## Verify a checkout

The canonical local quality gate formats, lints, tests, and validates the
workspace's generated artifacts:

```sh
cargo xtask check
```

See [Contributing](/docs/contributing) for focused checks and the complete test
strategy.

## Downloadable data and offline use

The completion SQLite database and command model are separate exact-version
assets, not part of the binary or Homebrew package. The website channel may
advance completion knowledge independently without cutting a binary release;
each database and required license notice has immutable, digest-named bytes and
its own source identity, while the compatible model record is retained. Missing
assets never delay the first prompt: Quirl uses built-in/local completion and
degraded natural-command retrieval while a bounded background update is
eligible.

Inspect or explicitly retry asset work with:

```sh
quirl assets status
quirl assets retry
quirl assets update
```

On macOS, admitted assets live below
`~/Library/Application Support/quirl/assets`. On Linux, they live below
`$XDG_DATA_HOME/quirl/assets`, or `~/.local/share/quirl/assets` when XDG is not
set. Retry metadata uses the matching `quirl/assets` platform cache directory.
A failed update does not replace an already valid generation.
