Decision report · accepted

Quirl’s extension language is Lua.

Rust owns Quirl’s shell, executor, built-ins, value model, and performance-critical logic. Lua 5.4 is the deliberately small, recognizable extension language for configuration, automation, and trusted plugins. Quirl supplies the missing modern experience with generated annotations, completion, linting, formatting, schema validation, and strict Rust boundary checks.

01 · ACCEPTED

Lua 5.4

The smallest measured runtime, a mature Rust bridge, decades of stability, and a language already familiar from terminal tools. Quirl adds the coherent SDK and IDE experience.

02 · TECHNICAL ALTERNATIVE

Strict Luau

Better ahead-of-time analysis, but a less familiar language identity plus a C++ analyzer bridge and VM/analyzer revision coordination that Quirl would have to own.

03 · RUST-NATIVE ALTERNATIVE

Rhai

Excellent host integration and resource controls, but a Quirl user must learn a smaller language with substantially less adjacent configuration and plugin adoption.

02 · What changed

Rust is the product language. The guest is an extension language.

The guest must be good at

Readable configuration, small automation scripts, prompt and completion extensions, typed command definitions, plugin hooks, fast reloads, capability-limited host calls, and actionable diagnostics.

The guest does not need to own

Process execution internals, job control, the parser, rendering, core data structures, performance-critical transforms, or the built-in command catalog. Those stay in Rust.

This favors a small, deeply integrated runtime over a general application ecosystem. npm or PyPI compatibility is less valuable than predictable embedding, while familiarity still matters because users—not only Quirl maintainers—will author plugins and configuration.

The product decision is broader than the numeric rank.

Quirl accepts Lua’s dynamic semantics because Rust owns the trusted core and validates every host boundary. quirl check can parse, lint, resolve capabilities, consume annotations, and validate schemas without execution, but it must not market that as sound static typing.

07 · Developer fit

Broad popularity and terminal-user familiarity are not the same thing.

What the broad data says

GitHub’s 2025 contributor data placed TypeScript first and Python second. Stack Overflow reported strong Python growth, while Rust remained the most admired language. This makes TypeScript and Python excellent familiarity signals—but does not establish that their ecosystems want an embedded CLI plugin language.

What adjacent terminal tools suggest

Neovim uses Lua for configuration and plugins and explicitly recommends annotations plus LuaLS for larger plugins. WezTerm uses a Lua script as configuration. This is stronger target-adjacent evidence for Lua-family familiarity than a web-wide language ranking, although it is still an inference rather than a Quirl user survey.

Use Lua’s name and ecosystem honestly.

Quirl uses Lua 5.4 source and .lua files, not a private dialect presented as Lua. The runtime environment is intentionally restricted, and the generated quirl API replaces ambient shell access with explicit capabilities.

The first usability validation should include Rust/CLI, shell/DevOps, JavaScript/TypeScript, Python, and Neovim/Lua users. Ask each participant to configure a prompt segment, write a command plugin, handle a structured error, and fix a lint or schema diagnostic. Time-to-correct-result matters more than a preference poll.

09 · Accepted decision

Lua

One familiar extension language, with Rust enforcing the contract.

Choose Lua 5.4 for configuration, scripts, and trusted plugins. Its familiarity, tiny footprint, longevity, and mature mlua bridge outweigh the stronger analysis offered by Luau. Quirl will deliver IDE-quality assistance through generated SDK annotations and metadata, while Rust schemas validate all values before state changes.

  1. Add a quirl-lua crate with pinned Lua 5.4 through mlua and a deliberately restricted standard library and module loader.
  2. Generate runtime bindings, LuaLS-compatible stubs, completion data, documentation, and AI schemas from one Rust host definition.
  3. Run one configuration, one script, and one prompt/completion plugin through the same capability API and structured error boundary.
  4. Ship the vertical slice with check, fmt, lint, test, cancellation, memory/instruction budgets, and last-known-good config reload.
DEVELOPER EXPERIENCE

Typed SDK, dynamic language

LuaLS-compatible annotations and generated metadata power completion and hover; Rust schemas remain authoritative.

SECURITY BOUNDARY

Capabilities, not ambient access

Trusted Lua receives explicit handles and budgets. Untrusted extensions remain out-of-process or WebAssembly.

DO NOT DEFAULT TO

TypeScript + QuickJS-NG

Keep it as an optional runner or revisit when TypeScript’s stable programmatic API and a compelling package story justify the complexity.

The durable record is ADR 0001: Lua is Quirl’s extension language. Revisit Luau only if real plugins demonstrate that annotations and schema validation are insufficient.

10 · Method and sources

Reproducible measurements, explicit judgment.

Footprint probes live in spikes/footprint. PocketPy’s official 2.1.8 amalgamated sources are checksum-verified by its runner. The Luau analyzer was built from official tag 0.734, stripped, and measured separately. TypeScript 7.0.2 was installed from its official npm package; the native arm64 checker and complete installed package were measured separately from the QuickJS-NG runtime.
