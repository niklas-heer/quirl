01 · Product thesis

One shell, three promises.

01 / ARRIVE

Old knowledge still works

External commands and common interactive Bash/Zsh syntax should paste and run without translation. Migration begins at zero, not at a tutorial.

02 / GROW

New power is explicit

A visible data mode changes the pipeline contract from bytes to values. There is no guessing which grammar the user meant.

03 / CREATE

Developer experience is the product

The prompt is a semantic editor: live diagnostics, typed completion, hover docs, previews, command palette, history, and project intelligence all ship together.

The central design decision

Do not create one magical grammar that heuristically guesses between Bash, Zsh, Nu, and a programming language. Create two legible modes, explicit bridges, and one shared runtime.

02 · Principles & boundaries

Ambitious, but honest.

Compatibility, structured data, rich UI, and a real extension language pull in different directions. The design works only if it names the boundary of each promise.

Must be true

Design principles

  • Instant, predictable interactive startup.
  • The first launch is already a great shell—no framework, prompt, fuzzy finder, or plugin pack required.
  • Plain command execution stays boring.
  • Mode is always visible and keyboard-switchable.
  • Values remain values until an explicit boundary.
  • Failures carry type, span, cause, and recovery hint.
  • Rich UI degrades to clean text over dumb terminals, logs, and SSH.
  • Everything built in is scriptable through a stable API.
Not promised

Non-goals for 1.0

  • Bit-for-bit emulation of every Bash and Zsh edge case.
  • Sourcing framework-sized .bashrc or .zshrc files into quirl state.
  • Replacing every Unix utility.
  • Owning terminal scrollback or becoming a terminal emulator.
  • Making native in-process plugins a stable ABI.
  • Guessing schemas from arbitrary text.
Product anchor: Helix’s coherence, Bun’s completeness.

quirl ships one deliberately integrated workflow: install one binary and immediately get editing, completion, fuzzy discovery, prompt context, structured tools, scripting, testing, formatting, documentation, and configuration. “Batteries included” means designed together and supported together—not a bundle of unrelated replacements for every Unix tool.

Name decision: Quirl.

A Quirl is a German kitchen whisk—roughly pronounced “kvirl”—from a word family associated with turning and stirring. The metaphor is deliberately simple: command syntax, typed values, embedded code, developer tooling, and plugins are mixed into one coherent environment. Product name: Quirl; binary: quirl; native data scripts: .quirl; extension scripts and configuration: .lua; environment prefix: QUIRL_.

03 · Interaction model

A modal shell, not a modal trap.

Like Vim, quirl gains power by changing what syntax means in a visible mode. Unlike Vim, every action has a textual form so sessions are reproducible and accessible.

Switch: Ctrl-Space
❯ docker ps | grep healthy
❯ for f in *.log; do gzip "$f"; done
❯ export RUST_LOG=debug
❯ cargo test --workspace

Bytes and processes

The default mode optimizes for muscle memory. Pipes carry bytes, quoting follows the compatibility grammar, non-zero exits set status, and familiar process control works.

Textual entry: mode command
Force external: ^ls

◆ ps | where cpu > 20 | sort cpu desc
◆ open users.json | get users | select name email
◆ http get /health | match {
    { status: 200, .. } => "up"
    error => error?
  }

Values and expressions

Data mode uses an unambiguous quirl grammar. Pipes carry typed, lazy values. External programs require an adapter or ^command; failures are Result values.

Textual entry: mode data
One-shot: data { ... }

Scripts never depend on invisible mode.

Interactive mode is session state. In files, data { ... }, command { ... }, and command literals make every grammar boundary explicit.

04 · Command intelligence

Completion is how users learn the interface.

Users should not memorize a command before they can use it. quirl builds a versioned semantic catalog of commands, subcommands, arguments, types, examples, effects, and documentation, then uses that catalog everywhere: completion, highlighting, hover, validation, generated docs, AI discovery, and plugins.

One command graph, many views.

The prompt does not ask separate plugins for strings. It asks the command graph what is legal here, why it is useful, what value shape it expects, what it will affect, and where that knowledge came from.

At the cursor

Completion explains itself

Suggestions show signature, type, summary, default, examples, conflicts, expected pipeline input/output, side effects, and provenance. The documentation panel follows selection without stealing keyboard focus.

As you type

Semantic highlighting

Color and style distinguish built-ins, external commands, script commands, flags, enum values, paths, variables, types, redirects, and errors. Existence, deprecation, trust, and destructive effects are visible without relying on color alone.

Ranking

Context beats popularity

Type compatibility, current subcommand, project, cwd, platform, recent local use, and exact prefix outrank global frequency. History may rank a valid item; it may not invent an interface.

Performance

Local first, slower later

The memory-mapped catalog answers immediately. Filesystem and project providers stream additions with cancellation. Selection never jumps when late results arrive.

Digest the completion ecosystem we already have

quirl imports existing definitions at index time and records their source and confidence. It does not execute arbitrary shell startup files on every keystroke.

Discovery

Installed truth, not model memory

The manifest includes only commands and plugins actually available in this installation, with schema hashes and versions. Agents can request the smallest relevant subtree.

Validation

Check before execution

check parses, resolves, lints, validates annotations, modules, capabilities, and known host schemas without running a Lua script. JSON diagnostics carry codes, spans, fixes, effects, and documentation links. It never claims sound static typing for arbitrary Lua.

Safety

Planning is separate from authority

The catalog describes capabilities; it does not grant them. Agent execution uses the same permission, preview, confirmation, and audit path as a human command.

Freshness

The binary is self-describing

Catalog generation is part of compilation and package validation. CI fails public commands with missing summaries, argument docs, types, examples, effects, or error codes.

The complete authoring toolchain ships with the shell

Writing a native or embedded Quirl automation should feel like a modern integrated toolchain: one install provides the formatter, checker, linter, test runner, documentation generator, language service, package tooling, and reproducible runner.

05 · Compatibility contract

“Compatible” needs a testable meaning.

quirl targets the copy-and-paste surface first. Full Bash and Zsh are separate, evolving languages with contradictory semantics; claiming complete dual compatibility would make the new language permanently ambiguous.

LevelPromiseExamplesImplementation
C0 · CommandsRequired for previewgit status, quoting, redirects, byte pipes, jobsNative process engine and POSIX-like lexer
C1 · Common interactiveRequired for 1.0&&, ||, globs, substitutions, loops, functions, exportsNative compatibility AST; corpus against Bash and Zsh
C2 · Dialect islandsRequired for 1.0bash { ... }, zsh { ... }, shebangsReference interpreter subprocess with structured capture
C3 · Source stateDeliberately partialImport cwd, exported env, aliases where representableState-diff protocol; reject traps and opaque functions
C4 · Exact emulationNo promiseEvery option, trap, framework, obscure expansionRun the requested bash or zsh
 
# Ordinary input: native, fast, familiar
for crate in crates/*; do cargo test -p "${crate##*/}" || break; done

# Dialect island: explicit and exact
bash {
  shopt -s globstar
  printf '%s\n' **/*.rs
}

# A script keeps its own authority
./legacy-deploy.sh        # kernel/shebang chooses its interpreter
bash ./legacy-deploy.sh   # explicit always wins

Compatibility rules

  • If input is valid in the C1 grammar, quirl executes it natively.
  • If input uses a Bash- or Zsh-only construct, quirl explains the mismatch and offers the exact dialect form; it does not silently reinterpret it.
  • source accepts quirl modules and a portable subset. source --bash and source --zsh import only representable state.
  • Behavior is versioned in a machine-readable matrix and backed by differential tests.

06 · Command & data surface

Small shell syntax. Strong values. Streaming by default.

quirl’s interactive data notation is expression-oriented and gradually typed, but deliberately remains a focused shell surface. It is parseable, formattable, and lintable; general-purpose modules and scripts use Lua 5.4.

# Literals carry meaning

# Pipelines stream typed records

| where modified < cutoff and size > limit
| select name size modified
| sort size desc
| take 20

# Reusable commands declare their contract
def stale-logs(root: Path = ".") -> Stream<Entry> {
  ls root | where type == file and modified < now() - 30days
}

# Destructuring and exhaustive matching
match (http get "https://service.test/health") {
  ok({ status: 200, body, .. }) => body,
  ok({ status, .. })            => error("unexpected status", status),
  err(e)                        => e.context("health check failed")?,
}
Decided

| means one thing per mode

Byte pipe in command mode; value pipe in data mode. In files the surrounding block fixes the meaning. Runtime inspection never changes syntax.

Decided

Boundaries are visible

from json, to json, lines, and ^external convert between byte streams and values. Automatic conversion is limited to declared schemas.

Decided

Values keep provenance

Values may retain spans, file origins, and command origins. Diagnostics can point back through a pipeline without contaminating equality or serialization.

Open detail

Type checker depth

Start with command input/output signatures and local inference. Decide later whether generic user types and traits belong before 1.0.

07 · A first-class ls

The directory is data, not terminal paint.

quirl’s ls is a built-in producer of Entry records. Rendering happens only at the terminal boundary, so the same command can power a grid, a table, JSON, a filter, or an interactive browser.

type Entry = {
  name: String, path: Path,
  type: file | dir | symlink | device,
  size: Size?, modified: DateTime,
  mode: Permissions, owner: String?,
  git: GitState?, target: Path?,
}

◆ ls                         # adaptive human view
◆ ls | where type == dir     # structured filter
◆ ls --all --long            # familiar flags remain
◆ ls | view tree             # renderer chosen explicitly
❯ ls | grep Cargo            # command mode emits compatible text
❯ ^ls -la                    # bypass built-in; run system ls

Fast path

Names and basic metadata render first. Git state, owners, MIME types, and directory sizes are lazy columns with cancellation and cache budgets.

Stable path semantics

Machine pipelines receive exact Path values, never icon-decorated or shell-escaped display strings. Non-UTF-8 paths survive on Unix.

Adaptive rendering

Width, terminal capability, and requested fields choose grid, table, or lines. --plain and non-TTY output are deterministic.

Interactive upgrade

ls --browse opens a Ratatui panel for preview, selection, bulk actions, and piping selected Entry values back into the prompt.

09 · Embedded language & runners

One familiar extension language, chosen on evidence.

Quirl needs one canonical general-purpose language for scripts, configuration, custom commands, prompt components, keymaps, and trusted UI extensions. The concise quirl command/data notation remains the interactive shell surface; it does not grow into a second general-purpose programming language.

Accepted decision: Lua 5.4.

Rust remains Quirl’s implementation language; Lua is the sole first-class language for configuration, automation, and trusted plugins. Familiarity, a 0.58 MiB measured runtime probe, decades of longevity, and the mature mlua bridge outweigh Luau’s stronger analyzer for this extension-only role. Open the decision report or read ADR 0001.

Implementation status: the first Lua slice is live.

The Rust workspace now embeds restricted Lua 5.4, generates LuaLS/JSON/Markdown SDK views, validates configuration through Rust schemas, atomically reloads config and plugins at safe prompt boundaries, and applies keymap, prompt, picker, and extension settings to the interactive editor. Data mode uses a focused native Rust grammar with typed predicates, dotted fields, sorting, and limiting. The rejected prototype runtime and all executable/dependency paths have been removed.

Dynamic does not mean unchecked.

Quirl generates LuaLS-compatible annotations, completion metadata, docs, and AI schemas from Rust host definitions. quirl check parses, lints, resolves modules and capabilities, and validates known schemas without execution. Rust validates every host value before mutation, but Quirl does not promise sound static typing for arbitrary Lua.

One runner, multiple language engines

quirl run is the stable script entry point. It detects a shebang or known extension, accepts an explicit --lang, and gives every engine the same arguments, environment, working directory, byte streams, cancellation signal, and structured exit result.

---@param ctx quirl.Context
---@return quirl.Result<quirl.Output, quirl.ShellError>
local function main(ctx)
  local env = ctx.args:required("env")
  local services = quirl.data.open("services.toml", quirl.schema.services)
  if not services.ok then return services end
  return quirl.process.run(
    "deployctl", { "apply", "--env", env }, services.value
  )
end

return { main = main }

Decision evidence: performance × developer experience

The runtime spike covers Steel, Lua, Fennel, Rhai, PocketPy, Luau, and QuickJS-NG, with the native TypeScript 7 checker measured separately. Raw speed alone did not choose Lua: language recognition, ecosystem longevity, IDE integration, safe interruption, and a maintainable Rust host bridge were evaluated together.

COLD STARTCreate VM, register the same host API, parse one module, invoke main.
WARM INVOKEExecute cached bytecode 10,000 times with scalar arguments.
HOST BOUNDARYRound-trip records and Result values across Rust callbacks.
DATA WORKFilter and aggregate 100,000 equivalent records in each runtime.
FOOTPRINTMeasure binary-size delta, VM resident memory, and cached-module memory.

Hard acceptance gates

The Lua integration must parse and lint without execution, power completion and hover from generated metadata, initialize P95 ≤ 1 ms, cross a warm scalar host boundary P95 ≤ 1 µs, support memory/instruction budgets and interruption, restrict module loading, preserve last-known-good configuration, and serve scripts, config, commands, and trusted plugins through one SDK.

Why Lua won.

The size-optimized Lua probe measured 0.58 MiB and 1.41 MiB peak RSS, the smallest mature baseline in the evaluation. Luau’s analysis is stronger, but its runtime plus analyzer measured roughly 6.65 MiB and requires a Rust/C++ analyzer boundary. TypeScript adds roughly 31 MiB installed plus an emit/runtime pipeline. For an extension layer inside a Rust product, Lua’s familiar name and lower complete-system burden are the better trade. Read the accepted decision report.

Typed selection

Preserve the value

The picker displays labels, highlights, metadata, and previews but returns the original value. Picking a Process, Path, history entry, or plugin record never round-trips through lossy display text.

Shared muscle memory

Predictable entry points

Ctrl-R searches structured history, Ctrl-T files, Alt-C directories, and Ctrl-K all actions. Shift-Tab expands completion into the full picker. Every binding is discoverable and remappable.

Interactive contract

Preview, reload, act

Single/multi-select, exact and fuzzy terms, inverse matching, source switching, live reload, safe previews, and named actions are built in. Providers stream candidates with cancellation and backpressure; rendering virtualizes large lists.

Script contract

The UI is also a command

pick accepts byte lines or typed streams and emits the selected values. --query, --multi, --preview, --format, and non-interactive fallback rules make workflows testable.

11 · Plugin platform

The shell is an environment you can grow.

quirl takes the extensibility of Emacs and Neovim seriously: users can add behavior without forking the shell or installing a loose constellation of commands. Trusted language plugins use the same typed values, command catalog, completion engine, UI compositor, diagnostics, and documentation system as built-ins.

Built-ins and plugins meet at the same public seams.

Core features may have privileged implementations for performance or job control, but their schemas, events, renderers, completions, docs, and user-facing composition use the public extension model. A plugin should feel native because it supplies the same metadata—not because it impersonates core.

Runtime

One Lua extension language

Trusted Lua plugins run in-process with capability handles, cancellation, allocation budgets, and per-callback deadlines. Generated annotations make the public SDK discoverable; Rust validation remains authoritative.

Isolation

Untrusted code gets a boundary

WebAssembly or out-of-process plugins use the same value and catalog protocols. A native Rust ABI is not stabilized; crashes must not take down the shell.

UI safety

Compose, do not fight for the terminal

Plugins return view trees or styled values. They cannot write arbitrary escape sequences into the active editor region. Layout, focus, theme, accessibility, and cleanup stay owned by quirl.

Supply chain

Permissions remain reviewable

The lockfile records package, checksum, source, capabilities, and resolved API version. Install and update show permission diffs; CI can deny unapproved sources or effects.

quirl plugin add github:acme/kubernetes-workbench
quirl plugin permissions kubernetes-workbench
quirl plugin enable kubernetes-workbench
quirl plugin doctor kubernetes-workbench
quirl plugin update --locked
quirl plugin disable kubernetes-workbench
quirl plugin remove kubernetes-workbench
Long-term direction

quirl can become a durable personal computing environment: install a focused plugin and gain commands, data types, views, automation, completions, docs, and AI-discoverable capabilities together. External programs remain first-class; plugins are an integration path, not a forced rewrite of the Unix ecosystem.

Conch lesson

AST-independent execution

Follow Conch’s separation of parser and runtime: compatibility and data ASTs lower to interfaces the executor can consume without knowing their surface grammar.

Flyline lesson

Rich UI in the shell process

Use Ratatui for responsive prompt widgets, fuzzy suggestions, tooltips, selection, and panels, while preserving scrollback and a plain fallback.

Nu lesson

Structured core, explicit bytes

Built-ins exchange typed streams. External commands remain byte-oriented and cross through visible adapters with bounded buffering.

Portability and terminal contract

  • Tier 1: Linux, macOS, and Windows; native job control behind one interface.
  • Capability negotiation for color, Unicode, keyboard protocol, mouse, hyperlinks, clipboard, and synchronized updates.

14 · Review board

The decisions to challenge now.

Use these local controls while reviewing. Choices and notes stay in this browser only; “Copy review” produces a Markdown summary for an issue or conversation.

Two explicit interactive modes

Command mode uses bytes and compatibility syntax; data mode uses typed value pipelines.

C0–C4 compatibility levels

Optimize copy/paste and common interactive syntax; use reference interpreters for exact dialect behavior.

Result-based errors outside command mode

Keep traditional status interactively, but require explicit failure handling in data pipelines and scripts.

Lua 5.4 as the extension language

Rust implements the product; one pinned Lua runtime and one generated quirl SDK serve configuration, scripts, and trusted plugins. Annotations improve tooling while Rust schemas enforce boundaries.

Batteries-included scope

Ship coherent navigation, discovery, data, view, developer-context, and operations capabilities.

One semantic command catalog

Completion, highlighting, docs, validation, AI discovery, and plugins consume one versioned CommandSpec graph.

Self-describing AI interface

Installed capabilities are exported as token-budgeted Markdown or canonical JSON, with check/format/lint tools and optional MCP access.

Lua plugin platform plus Wasm isolation

Trusted Lua plugins receive generated SDK metadata and explicit capabilities; untrusted and portable plugins use the same capability model through WebAssembly components.

Native typed fuzzy picker

History, files, completion, commands, data values, and plugins share one previewable, scriptable selection engine.

Lua configuration with synchronized views

config.lua is the source of truth; generated annotations, Rust schema validation, and local web/TUI views remain synchronized without creating another configuration store.

Open questions for Draft 0.9

  1. Which LuaLS-compatible annotation subset can Quirl generate and validate without bundling a fragile second source of truth?
  2. Should Lua 5.4 be statically linked and vendored on every platform, and what exact compatibility policy governs a future Lua 5.5 upgrade?
  3. Which standard-library modules and require behaviors are safe in config, trusted-plugin, and script contexts?
  4. How should instruction hooks, memory accounting, async cancellation, and per-callback deadlines interact across mlua callbacks?
  5. Should Wasm be limited to isolated plugins, or also be a first-class script runner?
  6. Is a persistent mode switch better than one mode with a separate structured pipe operator?
  7. How much dynamic Zsh/Bash completion code should run in workers instead of being translated and cached?
  8. Should the agent interface begin as CLI/JSON only, or ship the optional MCP server in preview?
  9. Which plugin hooks may mutate command plans, and what confirmation should that require?
  10. How much Bash/Zsh syntax belongs in native C1 before complexity harms diagnostics?
  11. Which fuzzy query language and scoring guarantees belong in the stable picker protocol?
  12. Which IDE surfaces and bundled capabilities are essential for the first preview?
